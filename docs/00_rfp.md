# ConsultDeck RFP（要求仕様書ドラフト）

## 1. 背景

近年、生成AIを活用した資料作成支援ツールが増加している。
一方で、コンサルティング業務における資料作成では、単純な文章生成ではなく、以下の要素が重要となる。

* 論理構造
* ストーリーライン
* 資料の型
* 読者適合性
* PowerPoint編集性
* レビュー容易性

既存の生成AIツールは「それっぽい資料」を生成することは可能であるが、実務レベルで必要となる構造化・編集性・再利用性には課題がある。

そのため、本プロジェクトでは、ローカル環境上で動作し、コンサル資料作成に特化したPowerPoint生成システム「ConsultDeck」を構築する。

---

# 2. 目的

ConsultDeckの目的は、PowerPoint資料を完全自動生成することではなく、コンサル資料作成における以下を高速化することである。

* 構成設計
* 資料の型適用
* 下書き生成
* 図解補助
* レビュー補助

AIは資料の最終品質を保証しない。
AIは構成・叩き台・図解補助を担当し、最終レビューは人間が行う。

---

# 3. システム概要

ConsultDeckは、ユーザー入力を基に、構造化されたSlideSpecを生成し、PowerPoint形式（.pptx）の資料を出力するローカル実行システムである。

## システム概要図

```text
User Input
  ↓
RequirementSpec
  ↓
OutlineSpec
  ↓
SlideSpec
  ↓
PPTX Renderer
  ↓
output/deck.pptx
```

# 5. 基本方針

* ローカル環境で実行する
* PPTXを正式成果物とする
* 人間が後編集可能な構造を維持する
* テンプレートベースで生成する
* AI任せの完全自動化を目的としない
* TDDで開発する
* GPUは時間分離で利用する

# 6. 機能要求

## 6.1 入力要求

ユーザーは以下を入力可能とする。

| 項目       | 内容            |
| -------- | ------------- |
| テーマ      | 資料テーマ         |
| 目的       | 提案、説明、報告など    |
| 読者       | 経営層、部長層、現場など  |
| 枚数       | スライド枚数        |
| 制約       | 記載禁止事項、対象範囲など |
| トーン      | フォーマル、戦略系など   |
| テンプレート指定 | 任意指定可能        |

---

## 6.2 テンプレート管理

テンプレートは後から登録・更新・削除可能とする。

### テンプレート管理項目

| 項目              | 内容        |
| --------------- | --------- |
| template_id     | 一意ID      |
| name            | テンプレート名称  |
| doc_type        | 提案、報告、分析等 |
| use_case        | 利用用途      |
| audience        | 想定読者      |
| phase           | 提案フェーズ    |
| slide_structure | スライド構成    |
| layout_rules    | レイアウト規則   |
| style_rules     | 配色、余白、文体等 |
| output_targets  | pptx等     |

### 初期テンプレート

| テンプレート | 用途       |
| ------ | -------- |
| 提案型    | 課題→解決→効果 |
| 分析型    | 事実→分析→示唆 |
| 報告型    | 状況→課題→対応 |

---

## 6.3 SlideSpec生成

システムは、資料構造を表すSlideSpecを生成する。

### SlideSpec構成例

| 項目          | 内容      |
| ----------- | ------- |
| slide_id    | スライドID  |
| title       | タイトル    |
| message     | 主張      |
| bullets     | 箇条書き    |
| diagram     | 図情報     |
| image       | 画像情報    |
| notes       | 発表者メモ   |
| layout_type | レイアウト種別 |

---

## 6.4 PPTX生成

システムはSlideSpecを基にPowerPointファイルを生成する。

### 要求事項

| 要求         | 内容                                      |
| ---------- | --------------------------------------- |
| 編集性        | PowerPointで編集可能                         |
| レイアウト      | テンプレート適用                                |
| 画像配置       | PNG差し込み                                 |
| 図形         | 可能な限りPPTネイティブ図形                         |
| 出力形式       | .pptx                                   |
| Renderer分離 | PPTX生成処理は差し替え可能な構造とする                   |
| MCP連携      | 将来的にMCP経由で類似のPPT作成機能を呼び出せること            |
| 接続設定       | MCP接続先・有効/無効・認証情報等を画面および設定ファイルから変更可能とする |

---

## 6.4.1 MCP連携要求

PPT作成部分については将来性を考慮し、MCP経由で外部または別プロセスの類似機能を呼び出せる仕組みを有すること。

### 要求事項

| 要求      | 内容                                     |
| ------- | -------------------------------------- |
| MCPアダプタ | SlideSpecをMCP呼び出し用の入力形式に変換できること        |
| 接続先変更   | MCPサーバーの接続先を変更できること                    |
| 設定方法    | 設定ファイルおよび画面から変更できること                   |
| 有効/無効切替 | 内蔵PPTX RendererとMCP Rendererを切り替えられること |
| フォールバック | MCP利用不可時は内蔵PPTX Rendererに戻せる構造とする      |
| 秘匿情報    | 認証情報は設定ファイル直書きではなく、環境変数等で扱える余地を持たせる    |
| ログ      | MCP呼び出し結果・失敗理由を記録できること                 |

---

## 6.5 レビュー機能

AIによるレビューを実施する。

### レビュー対象

| 項目     | 内容       |
| ------ | -------- |
| 論理性    | 話の流れ     |
| 冗長性    | 重複表現     |
| 読者適合   | 対象読者に合うか |
| 構造     | MECE性等   |
| テンプレ逸脱 | 型崩れ検知    |

---

## 6.6 画像生成

Stable Diffusionを用いて画像生成を行う。

### 用途制限

| 用途     | 利用可否 |
| ------ | ---- |
| 表紙     | ○    |
| 概念イメージ | ○    |
| 挿絵     | △    |
| 構造図    | ×    |
| 比較図    | ×    |
| グラフ    | ×    |

### 方針

* 画像は補助要素とする
* 資料価値は構造と論理に置く
* 全スライド画像生成は禁止する

# 12. 厳しめの前提

* AIだけで高品質資料は完成しない
* 人間レビューは必須
* 構造品質が最重要
* 見た目より論理を優先する
* 画像は補助要素に過ぎない
* Renderer分離を怠ると将来破綻する
